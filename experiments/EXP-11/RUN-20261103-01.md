## Outcome per sub-question

1. **Did content improve the known gaps? Yes.** A1 10/10 against EXP-09's 5/10; all 5 known gaps closed; 0 retrieval misses. The 5 gaps were content gaps, as EXP-09 concluded.
2. **Does it generalise? Mostly.** A2 8/10 correct + 2 partial, 0 wrong, on questions written before the memories and never shown to their drafter. Strict 80% falls short of the 90% bar; counting partials it is 100% answered with the core fact. Caveat: question writer and drafter read the same docs (limits below).
3. **Is retrieval a bottleneck? Not at 55 entries.** 1 retrieval miss in 20 answers, and read cost fell from 26 calls to 9–12 because the richer index lines let the arms route. The risk that remains is facts stored under a memory whose index line names another topic; the tool has no search to catch those.

Effect on the P4 scorecard's context retrieval score (2.5): that score is not re-scored here. This run shows that the 5/10 was a content gap that a gate-level memory practice closes, at the cost of one batch of ~24 memories written from the docs.

## Limitations and confounders

- **Same source for questions and memories.** The evaluator wrote questions from the repo docs; the drafter wrote memories from the same docs by a rule that covers ADRs, gates and experiments. 9 of 10 A2 answers sit in items the rule names explicitly (all but Q3, which an older memory, `p2-security-guards-and-lessons`, answered). Questions about conversations, PO intent or code would test a different coverage.
- **The coordinator saw both question sets.** It did not write memory text, and it froze the questions before the drafter started, but it chose the rule's wording and the drafter's file list after reading both sets. The rule follows the design @ultimate set before either set existed (every ADR clarification, gate criterion and experiment outcome).
- **n is small:** 10 questions per arm, one run per arm, one model family under test (Opus 5.5). One question is 10 points.
- **Self-grading:** the first scorer (Opus, coordinator) saw the key while preparing the arms. The second scorer (GPT-6.1) was blind to the first scores but not to the key, by design. Agreement 40/40.
- **Memory cost:** 21 more memories (+62%) for this content. With no search, each further batch adds index lines every branch reads at start; this run does not measure where that stops paying.
- **Arms start with a 55-line index** in their prompt: part of the answer comes from index lines (A2 Q6). That is part of the feature as shipped, as in EXP-09.
- **Apply change:** `source` is `#17868` for all ops, with file citations moved into bodies; one body lacks its `Sources:` line (above).
- **No infrastructure failure** in any participant (no `stopReason: error` reported; arms traced memory only).
