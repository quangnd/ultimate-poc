## Confounders / limitations

- **n = 1 per arm, 10 questions.** Coarse: one question is 10 points.
- **Question selection.** One evaluator (gpt-6.1-sol) chose what to ask, from docs. Doc-sourced questions favour arm B by construction: every reference has a file:line. Questions sourced from conversations or the PO's intent might favour memory instead.
- **Arm B is not memory-free.** It saw the same index, so "docs alone" is not isolated. It made 1 memory read.
- **Arm A could not search.** The `memory` tool has no search, so arm A read every entry. At 26 entries that is cheap; it would not scale.
- **Index lines in the prompt** carry part of memory's content (for example, the `p0-findings` line answers half of Q2). Arm A's score includes that prompt context, which is part of the memory feature as shipped.
- **Same tested model family** as the memory author (Opus coordinators). The evaluator and the second scorer used a different family; the first scorer (#12079, Opus) saw the key before scoring. The second scorer was blind to the first scores but not to the key, by design.
- **Infrastructure failures, left out of the metrics:**
  - **F17:** #12079's first model call (entry 12151) failed on a Claude Code upstream error. It was shared with #12097 (12150) and recovered by a manual resume from #52.
  - **F18:** arm A #12469's first call (entry 12542) failed on a Claude Code upstream error and was resumed by #52.
- **Comparison with the P0 probe** (EXP-01 RUN-20261101-01, 10/10). That probe's questions were written by the memory author, so it measured retrieval of what had been stored. This run measures coverage of what an independent reader thinks matters. The drop to 5/10 is the confound the probe named.
