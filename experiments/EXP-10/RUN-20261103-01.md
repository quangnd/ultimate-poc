## Procedure

**Pi arm** (`tools/run-pi.sh`). Fresh `git clone` from GitHub at `f70db2e`, then `npm ci`, then three passes, each `pi -p --no-session --mode json`:

1. **Build:** the builder model, given the task.
2. **Review:** the reviewer model, read-only, given the same review brief as the Ultimate reviewer.
3. **Fix:** the builder model again, given the task plus the review findings verbatim.

**Ultimate arm** (the new default flow):

- **Worker #17099** (`worker` definition, `isolate: worktree`, which runs `npm ci` as worktree setup) received the task verbatim.
- **Reviewer #17391** (`reviewer` definition) received the same review brief, pointed at the worker's worktree and the range `f70db2e..3543d8a`.
- The coordinator sent the findings verbatim to the same worker, which fixed them. There was no blind QA and no other coordination.

**Review rounds:** one per arm. Each first review returned one finding (see Defects), so each arm got exactly one fix pass, and no second round followed in either.

**Order:** Pi first (23:55:38–00:06:57Z), then Ultimate (00:07:38–00:18:14Z), on the same machine.

## Defects and cross-checks

**The one defect, identical in both arms.**
- **What:** both builders independently chose to show "Complete" instead of the finish date when every task of a side is done, and to hide the delta and slip. This contradicts AC 10. Code: Pi `src/web/ImportPreview.tsx:211–215` in `d8c91c0`; Ultimate `src/web/ImportPreview.tsx:103–108` in `3543d8a`.
- **Found by:** both reviewers.
  - Pi's reviewer rated it medium and reproduced it by importing an all-done copy of the sample.
  - Ultimate's reviewer rated it blocking from the code, without running the unit or E2E suites ("per reviewer instructions": the `reviewer` definition is read-only).
- **Fixed:** each builder fixed it in one pass and added a render test and an E2E test for the all-done case.
- **Missed by the hidden suite**, because the suite is domain-only. This is an instrument limit, as in EXP-08.

**Cross-checks:** each arm's own tests, from its final commit, were run against the other arm's final commit with `tools/crosstest.sh`.
- **Domain tests:**
  - Pi's `tests/domain/diff.test.ts` (45 tests) passes on Ultimate's code: 45/45.
  - Ultimate's (27 tests) passes on Pi's code: 27/27.
  - So neither arm's domain tests find a defect in the other arm.
- **UI tests:**
  - **Cross results:** `tests/web/import-preview.test.ts` failed 2/2 in both directions, and `e2e/import-preview.spec.ts` failed in both directions.
  - **Why:** every failure is a wording or selector mismatch, not missing behaviour. The two arms' tests target different text, "(complete)" against "(all tasks done)", and different region names, "What changes" against "What would change".
  - **Evidence:** `grades/x-*-unit.txt` keeps each failure's full `Received` text: the rendered preview of the other arm. In both directions it shows both finish dates, the delta (−28 / +28 working days) and both slips (2 → 30 and 30 → 2 working days early). The E2E failures are the same mismatch: a region name the other arm does not use (`grades/x-*-e2e.txt`).
  - So no extra defect is found. These tests are coupled to their own arm's UI text.
- **Reviewer findings cross-applied:** each reviewer's only finding applies to both first builds and to neither final build (above).

## Outcome

PASS: both arms produced complete measurements.
- On this task, with the same models, the two arms reached the **same quality**: 22/22 hidden on the first pass, the same single defect, fixed in one review round, and all three checks green.
- They took **about the same wall time** (10.5 against 11.3 min excluding setup).
- **Cost:** Ultimate's arm cost about 7 % more by the list-price proxy ($1.85 against $1.73), with 43 % more tokens and the same number of model calls. The difference is the worker's larger cached context per call.

## Confounders and limitations

- **n = 1, one task.** This is an observation, not a trend.
- **Order:** Pi ran first, then Ultimate, 10 minutes apart. Provider load and caching may differ between the two windows.
- **Task size is below the target.** The task was designed for at least 20 minutes, but both builders finished in 8.5–9.2 min of build time. It is about 3–5× larger than the EXP-08 tasks (1–3 min) and still below the PO's 20-minute bar.
- **The hidden suite is domain-only.** The one real defect was in the UI, and only the reviewers found it.
- **The reviewers are not identical.** They use the same model and the same brief, but Ultimate's `reviewer` definition adds its own system prompt and read-only stance. In this run it did not execute tests (32 s), while Pi's reviewer ran typecheck, the unit tests and E2E itself (68 s).
- **Cost figures are list-price proxies** on subscriptions (Copilot, Codex), not invoices. Token totals are dominated by cache reads.
- **Shared machine:** other conversations on the host were not controlled or counted during the run.
- **The grader is part of the system under test:** the coordinator, an Ultimate agent, designed, ran and graded both arms. The PR reviewer is the independent check.

## What the numbers support, and what they do not

- **Supported:** with the build and review models matched, on a feature-sized task (domain + UI + E2E, ~9 min of build), the lightweight Ultimate flow (one worker, a cross-family reviewer) matched plain Pi on correctness, review outcome and wall time, at a similar cost proxy (+7 %).
  - The 1.7× cost gap and 2.2× time gap of EXP-08 do not appear here. **Untested hypothesis:** they came from EXP-08's model mismatch and its heavier flow (blind QA), not from the harness. This run differs from EXP-08 in those two factors *and* in task, size and date, so it cannot separate them.
  - The cross-family review step paid for itself in both arms: it caught the only defect, which the domain hidden suite could not.
- **Not supported:**
  - Any claim that either tool is faster, cheaper or better in general (n = 1, a single order).
  - Any claim about tasks of 20+ minutes, which this one turned out not to be.
  - Any claim about Ultimate's durability or recovery benefits: nothing failed, so they were not exercised.
  - The coordinator's own overhead ($4.80 to the cutoff) is real cost of running Ultimate this way. A routine issue would carry a smaller coordinator share, but this run did not measure one.
