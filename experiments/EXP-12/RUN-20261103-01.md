- Date/time/time zone: 2026-11-03, 09:16Z–10:30Z (UTC). Valid arms ran 10:07:46Z–10:19:22Z.

- Ultimate version + commit: running host `/Users/mun/Projects/ultimate`, build `b7caa87` shown by every preview. Not restarted, not changed.
- Model/provider/configuration: **the same in all four arm runs**, proven from each preview's storage (see "Model equivalence").
  - @ultimate and coordinator: `claude-code/claude-opus-5-5` medium.

- Hypotheses (declared in advance in #68):
  - **H1:** L uses ≥ 25% fewer coordinator tokens with no more coordinator calls than O, on both tasks.
  - **H2:** L's quality is equal or better, with no extra interventions.
  - **H3:** every difference is traced to a named overlay rule.
- **Outcome: H1 FAIL, H2 PASS, H3 PARTIAL.** The lean overlay did not reduce coordinator tokens on single-issue work. It used 14% and 30% *more* tokens, and 6.6% and 11.6% more estimated cost. Quality was identical. It was faster (−24% and −12% branch time).

## Method change approved at the spike (PO, option 1a)

- **Finding (capability limitation):** the `instance` tool reads `instance.model` from the *host* project's settings, not from the previewed worktree's (`extensions/instance/server.ts` `previewModelSetting(host)` → `host.projectSettings()`). With `"instance": {"model": null}` in the arm worktrees, both spike previews still got `ULTIMATE_MODEL=openai-codex/gpt-6.1-sol` (seen with `ps eww`). Every agent would have run on GPT-6.1. A per-worktree `instance.model` is **NOT AVAILABLE**.
- **What ran instead:** `tools/start-arm.sh` starts the same `server/main.ts` with the instance tool's environment (own home, own copy of the user config, `ULTIMATE_INSTANCE_OWNER` = host pid 63722), but without `ULTIMATE_MODEL`.
  - Same network flag as the host: `--network-family-autoselection-attempt-timeout=2000`.
  - Tailscale off in each preview's private config copy, since the previews had published themselves on the tailnet.
  - The instance tool's startup checks and automatic cleanup did not apply: processes, homes and worktrees were stopped and removed by hand. Every start and stop, with pid, port, home and worktree, is in `ledger.txt`.
  - Before every stop, the process's environment was checked for its own `ULTIMATE_HOME`.

**Cache effects (why tokens ≠ cost):**
- Cache reads are 80–81% of every coordinator's tokens but only 8–9% of its cost.
- Cache writes are 17–22% of the tokens but **82–84% of the cost**: $8/M, 40× the read price.
- Each turn after a wake rewrote about 15–19k tokens of cache, in both arms. About 15k of each is the dynamic prompt section that changes when a child starts or finishes. That costs about $0.12–0.15 per wake.
- So cost follows the number of wakes, not the size of the context. L's extra calls cost little in cache reads and more in cache writes. That is why cost rose about half as much as tokens.
- This mechanism is the same in both arms and is not caused by the overlay.

## Confounds (PO rule 2)

- **Provider failures, 429s, model mismatches in the valid runs:** none. Every reply ended with `stopReason` `toolUse` or `stop`, with 0 error entries (`metrics/*.json`, `errors: []`). All models matched (table above).
- **Network flag:** on in every preview process, as on the host. Both arms were equal on this.
- **Void attempts**, excluded from all results (`ledger.txt`), all caused by my seeds or setup, not by either arm:
  - t1 attempt 1 (09:58Z): the seed said "coordinator branch". @ultimate used `subagent` (agent coordinator), which has no `subagent` tool, and both arms stopped blocked. Estimated cost: O $0.72, L $0.71.
  - t1 attempt 2 (10:04Z): the seed reached conversation 1 before @ultimate (#41) existed, so it had no `branch` tool. Cost: $0.03 each.
  - Fix: the seed names the `branch` tool and is sent to #41 once the UI shows it. Both arms received the identical fix.
- **Spike:** $0.54 (O) + $0.70 (L), not counted.

## Limitations

- n = 2 tasks × 1 run per arm, one machine, one evening. Differences of one or two calls are within what model variance could produce.
- The preview harness was started by hand (method 1a), not through the `instance` tool, and each preview was seeded through @ultimate, not by a human.
- One issue per branch was held constant. The overlay's first rule targets the multi-issue coordinator from P2 (64M tokens), which this design cannot test.
- Single-issue, small domain tasks with no review findings. The rules about relaying findings and blind QA were never exercised.
- The cost is an estimate from list prices. claude-code runs on a subscription.

## Interpretation

- On small single-issue tasks, the lean overlay does not save tokens or money. The coordinator's cost is dominated by per-wake cache writes, about $0.12–0.15 each, and the overlay added wakes: it looked up recorded exit codes instead of trusting the worker or running the checks itself.
- It did cut the coordinator's wall time, by not running e2e itself, and halved the size of child reports.
- The large P2 saving the overlay was written for came from one coordinator handling many issues. Here that is held constant in both arms, so this run says nothing about it.
